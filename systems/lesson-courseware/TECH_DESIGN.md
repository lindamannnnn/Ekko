# 教师工作台技术方案 —— 备课→上课→课后（免费生成式路径）

> 本文档是「免费做出能上课的课件」这条路径的**经验沉淀**。目标是：教师输入任意课题，系统免费地生成可上课的教案 + 课件，课后一键生成课评，串成一个工作台。
>
> 核心结论先行：**免费模型做不了"知识创作"，但"能上课的课件"根本不需要模型创作知识——知识来自教材（原料），模型只做组织与表达。**

---

## 1. 要解决的核心矛盾

| 诉求 | 约束 | 冲突 |
|---|---|---|
| 课件能直接上课（有算理/品析/例题步骤/答案正确） | 只能用免费模型 GLM-4-Flash | 免费模型生成内容空泛、算错题、编不出算理 |

**这个矛盾是假的**，因为它建立在一个错误假设上：*"课件内容 = 模型生成"*。

## 2. 破局：把"能上课的课件"拆成三件事

| 课件要什么 | 靠什么保证 | 需要模型吗 |
|---|---|---|
| **知识准确**（例题答案对、译文对、公式对、生字词对） | 教材数据（原料）+ 程序校验 | ❌ 不需要 |
| **结构完整**（有作者背景、生字词、例题步骤、分层练习、小结） | 生成协议（硬约束的页面清单） | ❌ 不需要 |
| **表达清晰**（把内容组织成流畅话术） | 免费模型（组织/翻译/润色） | ✅ 弱模型**恰好擅长** |

**结论**：免费模型的"硬伤"，是因为一直让它做不擅长的"知识创作"。正确做法是——**知识靠原料+规则确定性产出，模型只做它擅长的表达**。

## 3. 架构总览（三层）

```
┌─────────────────────────────────────────────────────┐
│  教材知识库（原料 · 一次性建设，非"写死课件"）        │
│  原文 original_text · 知识点 key_points · 公式 formulas │
│  （这 515 条 KB 已经是原料，教材事实是客观的、必须预置）│
└─────────────────────┬───────────────────────────────┘
                      ▼
┌─────────────────────────────────────────────────────┐
│  确定性生成引擎（规则 + 程序校验，零模型）             │
│  · 例题/练习：从公式规则生成题目，答案程序算           │
│  · 生字词：拼音(pypinyin) + 笔画(笔画库) + 释义(词典) │
│  · 数位表/分数条/数轴等图示：规则渲染 SVG              │
└─────────────────────┬───────────────────────────────┘
                      ▼
┌─────────────────────────────────────────────────────┐
│  免费模型（GLM-4-Flash，只做表达，不做知识创作）       │
│  · 教案生成：目标/重难点/过程/练习（课标 grounding）   │
│  · 话术润色：把确定性内容组织成流畅的讲解语言          │
│  · 译文：原文→译文（翻译任务，弱模型擅长）            │
└─────────────────────┬───────────────────────────────┘
                      ▼
┌─────────────────────────────────────────────────────┐
│  质量门禁（自审闭环，不通过就打回重来）               │
│  · 知识校验：答案程序验算、读法/改写/算式校验          │
│  · 结构校验：该课型的必含模块/字段非空才放行           │
│  · 三科教育专家 agent：每科一套确定性 check + LLM 审核 │
└─────────────────────────────────────────────────────┘
```

> **注：上面三层是「弱模型免费路径」（默认，GLM-4-Flash）**。当用户在表单填了强模型 API 时，自动切换「强模型独立链路」，**跳过确定性引擎的页面模板**，改由教师 AGENT 一次调用产出整份教学语义，程序确定性映射成页面。详见第 11 节。

### 三科教育专家 agent（审核层，`courseware_engine/experts.py`）

用户方案：每科一个「教学经验丰富」的 agent，给弱模型讲怎么生成教学层 + 按该科标准审核。落地为三层：

| 层 | 内容 | 能否程序化 |
|---|---|---|
| guide | 该科「好内容怎么生成」的固定协议（算理/品析/呈现·操练·应用三段式 + 禁止项 + few-shot） | 生成时注入 |
| check（确定性门禁） | 可程序判断的硬伤，命中即**阻断出片** | ✅ 能 |
| review_prompt（LLM 审核） | 弱模型语义审核（手法判对没/算理循环论证没/品析三要素齐不齐） | ❌ 只能报告 |

**确定性门禁清单（`check`，三科共用 `_common_check` + 各自专属）**：

- 通用：练习答案复述题目（空转）、中文文本截断（虚词结尾）、教学页模板套话（"同学们/想一想/布置作业"等跨课空话）。
- 数学：无计算类例题（概念课除外）、例题未覆盖课题核心（如"用字母表示数"只出解方程）、分层三档同题复制、算理=公式复述（循环论证）。
- 语文：古诗缺译文/赏析页、品析页缺三要素（意思/手法/好在哪）、品析用词义解释冒充句子品析。
- 英语：词汇教学页缺呈现/操练/应用三环节、单元标题句（What's he like?）未出现在正文。

**阻断出片 vs 报告的分界线**（诚实的能力边界）：

- `blocked`（阻断）= 确定性门禁命中——这些是**可程序化的硬伤**，改了 KB/引擎就能消，所以必须打回。
- `soft`（仅报告）= LLM 审核命中——弱模型的能力天花板（真算理深度、品析手法准确度），**重试和自审都兜不住**，只能靠升级更强模型（`AI_MODEL`）或人工补，不能假装能自动修好。

## 4. 核心原则：原料 vs 成品（这是"生成"和"写死"的分界线）

- ❌ **成品**（写死课件）= 把"教学加工结果"预置进去，如"例题：12/16 约分=3/4 的完整步骤""译文：横看是山岭侧看是山峰"——这是建"课程仓库直接取"，没有生成价值。
- ✅ **原料**（教材事实）= 只预置客观的教材数据：原文、知识点、公式、标准答案。**教学加工（例题步骤、练习变式、译文、赏析、话术）由规则/模型从原料生成**。

> 原料是"面粉"，成品是"面包"。我们要做的是"面包机"（规则引擎），不是"囤面包"（写死成品）。面粉必须买（教材事实客观存在），但面包机让同一袋面粉能烤出无数个不同面包。

## 5. 分工表（一图看懂什么该确定性、什么该模型）

| 任务 | 归属 | 工具/方法 | 质量保证 |
|---|---|---|---|
| 知识点/定义/公式 | 原料 | 现有 KB | 教材事实，不生成 |
| 例题题目 | 确定性生成 | 从公式规则构造 | 数据来自原料 |
| 例题答案 | 确定性生成 | 程序计算 | 100% 正确 |
| 例题步骤（算理） | 确定性模板 | 步骤模板 + 填入具体数字 | 模板固定 |
| 练习变式 | 确定性生成 | 逆运算/换数字规则 | 程序验算 |
| 生字词拼音 | 确定性生成 | pypinyin | 确定性 |
| 生字词笔画 | 确定性生成 | 笔画库 | 确定性 |
| 生字词释义/组词 | 确定性生成 | 词典（或免费模型+校验） | 可查 |
| 英语音标 | 确定性生成 | eng_to_ipa | 确定性 |
| 译文 | 免费模型 | 翻译任务 | 原文对应校验 |
| 赏析/品析 | 免费模型 + 模板 | 要点模板 + 模型润色 | 自审 |
| 教案 | 免费模型 | k12 SKILL 课标 grounding | 课标校验 |
| 话术润色 | 免费模型 | 组织表达 | 自审 |
| 图示 | 确定性渲染 | SVG 规则 | 确定性 |

## 6. 生成协议（页面结构硬约束）

**语文 8 模块**：封面 → 目标 → 作者背景 → 生字词(音形义组词) → 朗读指导(节奏/韵脚) → 诗意译文(一句一译) → 意境赏析(意象/画面/手法/诗眼) → 拓展延伸 → 板书 → 分层作业 → 总结

**数学**：导入 → 概念(算理,每步"为什么") → 例题(完整步骤+答案+方法) → 变式/易错 → 分层练习(带答案) → 小结

**英语**：导入 → 词汇(音形义+例句) → 句型/语法(规则+例句) → 操练 → 对话/短文 → 输出 → 小结

## 7. 免费模型绕过硬伤的五个手段

1. **不让它创作知识**：知识从原料+规则来，模型只填表达。
2. **给足约束 + few-shot**：每个生成点都带"结构样例 + 硬性要求"。
3. **程序校验兜底**：答案/读法/改写/算式能程序验的，一律程序验。
4. **自审闭环**：生成后按五类清单自审，发现问题自改，改完再审。
5. **确定性优先**：能规则的绝不用模型，模型只做规则覆盖不了的"表达"。

## 8. 工作台串联

```
老师登录 → 建班级/学生（系统A已有）
  ├─ 备课：输入课题 → 免费模型生成教案 → 确定性引擎生成课件 → 自审 → 可上课课件
  ├─ 上课：放映课件
  └─ 课后：录入学生表现 → 系统A生成课评（已在用 GLM-4-Flash）
```

## 10. 可复用性（这套经验怎么复制到其他场景）

- 换学科：往"教材知识库"加该学科的原料（原文/知识点/公式），确定性引擎和生成协议不变。
- 换学段：改生成协议里的学段适配（如低年级视觉、目标难度）。
- 换模型：确定性引擎不依赖模型，免费模型层可随时替换（弱→强）而不影响确定性部分。

## 11. 免费模型路径做到顶 + 升级 API 路径（产品决策）

**默认路线**：GLM-4-Flash 免费做到极致——确定性引擎承担所有知识/答案/结构，弱模型只做译文/赏析/教学展开的表达，门禁只阻断"可程序化硬伤"。

**升级路线（已留口，不改架构）**：网页表单「模型配置」可填 `AI_BASE_URL` / `AI_MODEL` / `AI_API_KEY`，覆盖 `.env` 的免费配置。换了更强模型，确定性层完全不动，只有 LLM 层的品析/算理深度变好——这是"留一条升级 API 的路径"的落地。

**强/弱模型分离路径（关键架构决策）**：弱模型和强模型的生成方法**不能复用同一套**，否则强模型会时间/token 爆炸。

| 维度 | 弱模型路径（默认，glm-4-flash） | 强模型路径（用户传强模型 API 时自动切换） |
|---|---|---|
| 判定 | `LLMClient.is_strong()`：模型名含 flash/lite/mini/turbo/air/tiny 判弱 | 其余判强 |
| 内容生成 | `auto_kb` 确定性引擎生成 90% 页面 + `teach_expand.py` 逐例题小调用填空隙 | **教师 AGENT（`strong_gen.py`）一次调用输出「教学语义」LessonContent（目标/导入/概念/例题/分层练习/作业/小结/板书/示意图），程序 `content_to_segments` 确定性映射成页面** |
| 输出契约 | 直接产 segments（layout/slots 技术结构） | 产出语义 JSON（objectives/examples/practice），不碰渲染层 |
| max_tokens | 600~1500 | `complete()` 自动抬到下限 **8000**（推理模型先花 token 思考） |
| 自审闭环 | 有（弱模型老出错，需审核打回） | **免**（强模型一次做对，审核是浪费） |
| 语义审核 | `llm_review` 跑 | 跳过（`soft` 置空） |
| 数学配图 | `_auto_diagrams` 按课题关键词猜通用图 | 教师 AGENT 输出 `diagrams`（5 类 SVG + 本课真实数字），程序精确画图 |

**为什么强模型不能复用弱模型那套**：推理型强模型（deepseek-v4-pro 等）每次调用先花大量 token 在 `reasoning_content`（思考过程）上，600 token 全耗在思考、最终 `content` 为空——引擎拿到空串静默跳过（表现为品析页/教学展开页不生成）。且"逐页多次 + 自审打回"让每次调用都从头思考，时间和 token 指数爆炸。正确做法：**一次大调用、max_tokens 给足、免自审**。

**强模型输出结构漂移（稳定性关键经验）**：强模型即使协议写清楚，仍会偶发/稳定地输出错误结构——实测三种：① 分层档位写成单对象而非数组；② summary 键名漂移（patterns/words 而非 points/formula）；③ board 键名漂移（words/patterns 而非 center/branches）。**这些漂移对同一课是稳定的，重试无效**（重试只是重复同样的错）。根治：**协议钉死结构 + 解析层归一化兜底**（`schemas.LessonContent.from_dict` 里做类型防御 + 键名归一化）。实测根治前 9 课成功率 77.8%、总耗时 56 分钟，根治后 9/9 成功、32 分钟。

**能力边界（诚实告知）**：弱模型产不出真算理（循环论证）、产不出准品析（手法错判），这是模型天花板不是流程 bug；确定性门禁只能消除"可程序化硬伤"，语义层靠升级模型或人工补。实测对比：同一课《题西林壁》，弱模型 GLM-4-Flash 审核残留 5 处语义问题，强模型 deepseek-v4-pro 审核通过（手法正确判"借景说理"、品析三要素齐全、换字对比到位）——升级路径验证有效。

---

*一句话记住：**免费的生成式课件 = 教材原料 + 确定性规则引擎 + 弱模型只做表达 + 程序校验自审**。*
