# 强模型课件生成提示词设计（三科）

> 目的：不再让强模型"自由发挥输出 JSON 结构"，而是先定义清楚**每科一份好课件该有哪些页、每页内容合格的标准**，把这套标准写成固定提示词（协议），强模型只按协议填充内容。程序负责校验 + 渲染，不负责"教什么"。
>
> 上一轮的教训：让强模型直接输出 segments（layout/slots 技术结构），键名漂移（layout/layout_id/type 乱跳），导致硬跑+打补丁。正确做法是**用自然语言把"好课件"讲清楚**，输出一个稳定的、语义化的 JSON，程序再映射成 segments。

---

## 一、三科好课件的页面结构（协议的地基）

### 数学（8 类页面）
| 顺序 | 页面 | 合格标准 |
|---|---|---|
| 1 | 封面 | 课题 + 年级·数学 |
| 2 | 学习目标 | 3-4 条，绑定本课知识点，禁止"结合实例感受数学与生活的联系"这类套话 |
| 3 | 情境导入 | 真实生活情境 + 一个引导问题，禁止照抄教材原文清单 |
| 4 | 核心概念 | 1-2 页，把本课概念讲清楚（定义/公式/用法） |
| 5 | 例题 | 2-3 道，每道有**完整解题步骤**（笔算要写竖式），答案正确 |
| 6 | 示意图 | 1-2 个，用**本课例题的真实数字**画（强模型描述 → 程序画 SVG），5 类类型：分数条/数轴/条形图/方格图/数位表 |
| 7 | 分层练习 | 基础/提高/拓展三档，**有梯度、不可同题复制**，每题有真实答案 |
| 8 | 小结 | 本课要点 3-5 条 + 公式/口诀 |
| 9 | 板书 | 中心词 + 2-4 个分支（概念/方法/易错） |
| 10 | 分层作业 | 基础/提高/拓展三档，**必须是具体题目+具体答案**，禁止元指令 |

### 语文（9 类页面）
| 顺序 | 页面 | 合格标准 |
|---|---|---|
| 1 | 封面 | 课题 + 年级·语文 |
| 2 | 学习目标 | 3-4 条，绑定本课，禁止套话 |
| 3 | 情境导入 | 真实情境 + 引导问题 |
| 4 | 作者/背景 | 有作者则出（作者名/朝代/出处），无则跳过 |
| 5 | 阅读提示 | 本课学习重点（从 key_points 提炼） |
| 6 | 段落理解 | 逐段首句 + 一句学习提示，1-3 页 |
| 7 | 重点句·品析 | **必须三段：意思/手法/好在哪，缺一不可**，手法判断要准确 |
| 8 | 分层练习 | 三档有梯度，每题真实答案 |
| 9 | 小结 | 主旨 + 写法 + 重点词句 |
| 10 | 板书 | 中心词 + 分支（内容/结构/写法/词句） |
| 11 | 分层作业 | 三档，具体题目+具体答案 |

### 英语（8 类页面）
| 顺序 | 页面 | 合格标准 |
|---|---|---|
| 1 | 封面 | 单元名 + 年级·英语 |
| 2 | 学习目标 | 3-4 条，绑定本课句型/词汇 |
| 3 | 情境导入 | 真实对话情境 |
| 4 | 词汇卡 | 本课词汇（音标由程序生成，模型只填 word/meaning/example） |
| 5 | 核心句型 | 本课重点句型 |
| 6 | 词汇·句型教学 | **必须三段：呈现/操练/应用，缺一不可** |
| 7 | 分层练习 | 三档有梯度，每题真实答案 |
| 8 | 小结 | 句型 + 词汇 + 表达 |
| 9 | 板书 | 中心词 + Words/Patterns 分支 |
| 10 | 分层作业 | 三档，具体题目+具体答案 |

## 二、通用硬性规则（三科都注入）

1. **答案必须正确**（数学会程序验算；语文英语答案要真实可核对）。
2. **分层三档不可同题复制**，基础<提高<拓展 有难度梯度。
3. **作业必须是具体题目**，禁止"完成课本习题""讲给家长听""抄写生字"这类元指令空话。
4. **禁止空壳页**（每页必须有真实内容）。
5. **禁止截断**（每句话写完整，不半句结尾）。
6. **内容 grounded 在教材原文**，不编造作者、公式、数据。
7. **禁止教案话术**（"同学们""大家看""想一想"），每页都是可投影的教学内容。

## 三、输出格式（固定 JSON schema，程序据此映射成 segments）

强模型输出一个稳定的语义化 JSON，**键名固定**，不暴露渲染层技术细节：

```json
{
  "title": "课题",
  "objectives": ["目标1", "目标2", "目标3"],
  "lead_in": {"scenario": "真实情境", "question": "引导问题"},
  "concepts": [{"statement": "知识点标题", "points": ["要点1", "要点2"]}],
  "examples": [{"problem": "题目", "steps": ["步骤1", "步骤2"], "answer": "答案", "method": "方法"}],
  "diagrams": [{"type": "bar_model", "total": 12, "parts": [{"value": 4, "label": "4"}], "caption": "..."}],
  "practice": {"basic": [{"q": "...", "a": "..."}], "standard": [...], "advanced": [...]},
  "summary": {"points": ["要点1", "要点2"], "formula": "公式"},
  "board": {"center": "课题", "branches": [{"label": "概念", "items": ["..."]}]},
  "homework": {"basic": [...], "standard": [...], "advanced": [...]}
}
```

程序（`strong_gen.py`）拿到这份语义 JSON 后，**确定性映射**成 segments（cover/objectives/lead_in/concept/steps/diagram/tiers/summary/board），再走 content_fill → validate → render。映射是稳定的代码，不靠模型猜。

## 五、结构漂移的三种类型与根治（稳定性关键经验）

强模型（推理型）即使协议写清楚了，仍会**偶发/稳定地输出错误结构**。实测抓到的三种漂移：

| 漂移 | 表现 | 根治 |
|---|---|---|
| ① 档位写成单对象 | `basic` 应是 `[{q,a}]` 数组，被写成单个 `{q,a}` | 协议钉死"必须数组" + 解析层单 dict 自动包成数组 |
| ② summary 键名漂移 | 协议要 `points/formula`，被写成 `patterns/words` | 解析层归一化 patterns/words → points |
| ③ board 键名漂移 | 协议要 `center/branches`，被写成 `words/patterns` | 解析层归一化 words/patterns → branches |

**关键教训**：这些漂移对同一课是**稳定的**（同一 prompt 每次都输出同样错误），所以**重试无效**——重试只是重复同样的错。正确做法是**协议钉死结构 + 解析层归一化兜底**双管齐下，而不是靠增加重试次数。

**稳定性实测**：根治前 9 课成功率 77.8%（2 课稳定漂移，重试 4 次全失败、单课耗 565-620 秒）；根治后 9/9 成功（100%），总耗时从 56 分钟降到 32 分钟。

## 六、为什么这样设计（对上上一轮"越修越奇怪"的根因）

| 之前的问题 | 现在的设计 |
|---|---|
| 强模型直接输出 segments（layout/slots 技术结构） | 强模型输出语义化内容（objectives/examples/practice），不碰渲染层 |
| 键名漂移（layout/layout_id/type 乱跳） | 键名固定（objectives/lead_in/examples），漂移即解析失败可重试 |
| 分层同题/作业元指令来自确定性引擎模板 | 强模型自己写分层/作业，程序只校验不代写 |
| 越修越奇怪（在模板里打补丁） | 模板只做"映射"不做"内容"，内容全归强模型 |
| 数学课件无配图 | 强模型输出 diagrams 语义（5 类 SVG + 本课真实数字），程序精确画图 |
