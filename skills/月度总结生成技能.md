# 月度总结生成技能

## 技能描述

根据学生某个月份的所有课堂表现记录，为每个学生自动生成一份结构化的月度表现总结，严格遵循6点结构，并保存到对应学生文件夹的 `summaries/` 目录下。

---

## 前置条件

在执行生成前，确保以下数据已经就绪：

1. **课后小结已保存**
   - 路径：`.claude/memory/class/{班级}/summaries/YYYYMMDD_{课程编号}_班级反馈.md`
   - 必须包含：「本节课核心知识点」「高频易错点」「课堂整体表现」「各娃表现」

2. **学生课评已保存**
   - 路径：`.claude/memory/class/{班级}/{学生姓名}/feedback/YYYYMMDD_{课程编号}.md`
   - 请假课次的文件名需包含 `(请假)`，会被自动排除

3. **API Key 已配置**
   - `.env` 文件中已配置 `KIMI_API_KEY`

---

## 使用方法

### 一键生成（默认5月，CSP01+CSP04）

```bash
cd d:/001/class-review-system
python tools/student-processing/generate_monthly_summary.py
```

脚本会自动：
1. 扫描指定班级的所有学生
2. 收集该月课后小结和学生课评
3. 调用 Kimi API 为每个学生生成6点结构月度总结
4. 输出汇总文件到 `output/`
5. **自动拆分**保存到每个学生的 `summaries/` 文件夹

### 生成其他月份

```bash
# 生成6月总结
python tools/student-processing/generate_monthly_summary.py --month 06

# 生成其他年份
python tools/student-processing/generate_monthly_summary.py --year 2026 --month 06
```

### 指定班级

```bash
# 只生成CSP01
python tools/student-processing/generate_monthly_summary.py --classes CSP01示例周六0830

# 生成多个班级（逗号分隔，不要空格）
python tools/student-processing/generate_monthly_summary.py --classes CSP01示例周六0830,CSP04示例周六1610
```

### 只生成汇总文件，不拆分到学生文件夹

```bash
python tools/student-processing/generate_monthly_summary.py --no-distribute
```

## 输出格式（严格6点结构）

每个学生的月度总结必须严格包含以下6个部分，使用 `## ` 作为标题：

### 1. 本月学了什么
- 用学生和家长都能听懂的语言概括当月核心知识点
- 不要罗列条目，写成一段流畅的话
- 系统题/选择题/判断题不要说具体题目名称

### 2. OJ数据表现
- 客观描述做题表现：哪节课完成了哪些题目、卡在哪几题
- 哪节课表现最好，哪节课需要加强
- **如果OJ数据不可靠，从课后小结「各娃表现」中推断，绝不编造数据**
- 系统题（单选题/判断题）不要说具体题目名称

### 3. 1-3个具体进步
- 每个进步必须有具体例子支撑（某节课、某道题、某个行为）
- 不能用空话套话

### 4. 1-3个具体问题
- 每个问题必须有具体例子支撑
- 要真实反映学生反复出现的问题

### 5. 1-3个具体训练建议
- 针对第4点的问题给出可操作建议
- 具体到"练什么、怎么练"，不要泛泛而谈

### 6. 老师综合评价
- 80-120字的亲切评语
- 示例老师口吻：有温度、有肯定、有期望

---

## 语气与格式规范

### 语气要求
- **模仿示例老师真实语气**，像真正了解学生的老师在跟家长沟通
- 具体、有细节，禁止空话套话
- 优点与不足比例保持 6:4 或 7:3
- 禁止使用："非常优秀""特别出色""超级棒"等过度夸张词汇
- 不使用"第5题""第3题"表述，必须说具体题目名称如「礼盒排序」
- 系统题用"系统题""选择题""判断题"代替具体名称

### 文件规范
- 每个部分用 `## ` 标题
- 文件命名：`{year}-{month}_月度总结.md`（如 `2026-05_月度总结.md`）
- 文件开头：`# {学生姓名} {year}年{month}月月度总结`
- 输出位置：`.claude/memory/class/{班级}/{学生姓名}/summaries/`

## 技术细节

### 依赖
- Python 3.x
- `requests`（Kimi API 调用）
- `python-dotenv`（读取 API Key）

### API 配置
- 模型：`moonshot-v1-8k`
- 温度：0.7
- 系统角色：示例老师（经验丰富、语气亲切专业的C++编程老师）

### 数据源优先级
1. **课后小结**（`summaries/`）→ 提取核心知识点 + 各娃表现
2. **学生课评**（`feedback/`）→ 补充个人细节
3. **OJ数据**（`oj/analysis/`）→ 仅作为参考，不可靠时弃用

---

## 注意事项

1. **请假处理**：文件名包含 `(请假)` 的课评会被自动排除
2. **OJ数据不可靠**：如果OJ平台数据显示全0分或不完整，脚本自动从课后小结文字中推断做题表现，不会编造数据
3. **课程编号偏移**：CSP04班级的本地编号与OJ编号有±1偏移，OJ相关逻辑中已自动处理
4. **手动验证**：生成后建议抽查1-2个学生的总结，确认事实准确性
5. **通用性**：通过 `--year` 和 `--month` 参数可生成任意月份的总结
