# 安全加固记录（2026-08-04）

针对「上线前必改」清单中的 CSRF / SECRET_KEY 两项，以及用户重点关注的「课件上传防漏洞」，
本次完成以下加固。所有改动已重启服务（端口 5000）并端到端验证通过。

## 一、本次已完成的加固

### 1. SECRET_KEY 改为环境变量注入（🔴→✅）
- 文件：`app.py`
- 旧：`SECRET_KEY = os.environ.get('SECRET_KEY', 'dev-secret-change-in-prod')`（硬编码弱默认值）
- 新：优先读 `SECRET_KEY` 环境变量；未设置时本地随机生成 `secrets.token_hex(32)` 并打印告警。
- 效果：源码/旧 git 历史泄露不再能伪造登录 session；本地仍可零配置启动。

### 2. CSRF 防护全局开启（🔴→✅）
- 文件：`app.py` `WTF_CSRF_ENABLED = True`（原 `False`）
- 配套：
  - `templates/base.html` + `templates/admin/base.html`：新增 `<meta name="csrf-token">` + 全局 `fetch` 钩子，
    自动为所有 `POST/PUT/DELETE/PATCH` 的 fetch 请求附带 `X-CSRFToken` 头（覆盖上传、删除、生成等接口，
    **避免开启 CSRF 后把前端接口打挂**）。
  - `templates/admin/login.html` 与 `templates/admin/users.html` 删除表单：补隐藏 `csrf_token` 字段。
  - `reviews` 蓝图保持整体豁免（纯 JSON API，仍受 `@login_required` 保护）。
- 验证：无 token 的登录 POST → 400 拦截；带 token → 正常 302。

### 3. 课件上传安全校验（🔴→✅）— 防「上传进后台」
- 新增 `src/security/upload_check.py`：
  - **扩展名白名单**（txt/docx/pptx/doc/pdf）+ **文件头魔数校验**（%PDF / PK / OLE），
    拦截「改名绕过」（如 `evil.exe` 改名 `evil.pdf`）。
  - **解析文本长度上限（~1.5MB）**，拦截「解析炸弹」（恶意 docx/pdf 解压出超长文本拖垮内存）。
  - **大小上限 10MB** 统一在校验内处理。
- 接入：`src/lessons/routes.py`（`_save_courseware`）与 `src/classes/routes.py`（`upload_course`）。
- 重要前提：上传目录 `uploads/` **不对外静态托管**（仅内存导出文件用 `send_file`），
  已上传文件无法被 URL 直接访问，因此无「上传 html/svg 触发存储型 XSS」路径。
- 验证：合法 PDF → 200；改名 exe.pdf → 400 拒绝；超长文本 → 400 拒绝。

### 4. 管理员密码随机化（🟡→✅）
- 文件：`app.py`
- 旧：`os.environ.get('ADMIN_PASSWORD', 'admin123')`（弱默认 `admin123`）
- 新：未设置 `ADMIN_PASSWORD` 时生成本地随机 16 位密码并打印到日志，提醒记录/固化。

### 5. 登录失败限流（🟡→✅）— 防暴力破解
- 新增 `src/security/ratelimit.py`：基于（客户端 IP）的滑动窗口限流（60s 内 ≤10 次），超限返回 429。
- 接入：`src/auth/routes.py` 登录、`src/admin/routes.py` 后台登录。
- 说明：内存级，单实例有效；多实例部署需换 Redis 等共享存储。

## 三、仍需你决定 / 后续建议（未自动改，避免动到部署方式）

1. **生产部署配置**（非代码问题）：当前仍跑 Flask 开发服务器。上线应换 `waitress`/`gunicorn` + HTTPS。
2. **环境变量固化**：生产环境务必设置 `SECRET_KEY`（固定随机串）、`ADMIN_PASSWORD`（固定）、
   `ADMIN_EMAIL`，并确认这些值不进 git（`.env` 当前未被追踪，已 OK）。
3. **多实例限流**：若以后多进程/多机部署，`ratelimit.py` 需换共享存储。
4. **CLAUDE.md / README 过时**：仍在描述已删除的旧架构，建议重写（不影响安全，影响可维护性）。
5. **SQLite 无自动备份**：一学期数据都在单文件，建议加定时备份脚本。
