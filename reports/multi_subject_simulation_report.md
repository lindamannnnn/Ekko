# 多智能体模拟：各学科连续课评生成体验报告

> 生成时间：2026-08-04
> 测试方式：每个学科用一个「模拟用户」智能体，**真实走生产 HTTP 链路**（建班 → 加学生 → 建独立课次并粘贴课程内容 → 选标签 + 写评语 → 调 AI 生成），连续生成第 1–5 课课评，不改动系统任何代码。
> 账户：teacher1@local.dev（同一教师，7 个独立班级 + 7 名学生）
> 模型：GLM-4-Flash（与线上一致，弱模型、依从度有限）

---

## 一、测试背景与目标

用户要求：**每个学科都由智能体模拟真实用户**，连续写出 1–5 课课程内容、自评、贴标签，并据此生成课评；再从**家长视角**与**用户（教师）视角**两条线，总结使用体验与家长看到课评后的真实反馈。本报告不修改系统，仅如实记录模拟过程、生成结果与双视角体验。

覆盖学科（含预置 code）：编程 coding、美术 art、舞蹈 dance、体育 sports、书法 calligraphy、英语 english、学科辅导 tutoring，共 **7 个学科 × 5 课 = 35 份课评**。

---

## 二、模拟方法（真实用户操作链路）

每一步都走生产路由，未走任何捷径：

1. `POST /classes/new` 建班（班级名如「模拟-coding-浩浩」，类型 = 学科 code）
2. `POST /classes/<id>/students/add` 加 1 名学生（带昵称，如浩浩 / 满满 / 雅雅）
3. 对第 1–5 课，依次：
   - `POST /classes/<id>/create_lesson_from_course` **粘贴本节课真实课程内容**（如「for 循环与 range、计算 1-100 偶数和」）
   - `POST /reviews/by-keys/<class>/<lesson>/<student>/generate` 传入 `teacher_comment`（教师手写一句话评语）+ `perf_tags`（教师点选快捷标签）
4. 抓取每份「用户真实输入」与「AI 输出」落库，供本报告引用。

每课由模拟用户**亲手撰写**课程内容、评价、标签，例如编程 L4：

```
课程内容：1. while 语法与退出条件；2. break/continue；3. 猜数字游戏循环版
标签：概念混淆 / 需多次提醒 / 敢于试错
评语：while 容易写成死循环，需要反复提醒加退出条件
```

## 四、各学科生成样本（家长视角看到的真实课评）

> 以下为系统实际生成原文（仅删空格冗余），反映家长打开课评时看到的样子。

### 编程 coding · 浩浩 · L4（标签：概念混淆 / 需多次提醒 / 敢于试错）
> 浩浩，本次编程课你独立完成了猜数字游戏循环版（while + if）这个任务，你对 while 循环和 break/continue 的掌握有了初步的认识。……虽然你在理解 while 循环和 break/continue 时遇到了一些困难，但你的敢于试错的精神值得表扬👍。在课堂上，你多次提醒后逐渐理解了 while 循环的退出条件……不过，需要注意的是，你在实际应用时容易写成死循环，需要老师在旁边反复提醒。

### 舞蹈 dance · 雅雅 · L4→L5（标签：略显害羞 → 富有感染力）
> L4：雅雅，今天你在课堂上的表现很棒，虽然一开始有些害羞，但在老师的鼓励下，你多次练习后动作更加流畅了。……老师注意到你在人前跳的时候会有些害羞，这是很正常的。
> L5：雅雅，今天的舞蹈课你表现得非常出色，动作规范且富有感染力，展示时完全放开了，非常自信。

### 书法 calligraphy · 墨墨 · L3（标签：需练基本功 / 易急躁）
> 墨墨，今天在永字八法的练习中，你展现了较好的握笔习惯和规范的坐姿，但你的速度有些快，导致在书写过程中显得有些急躁。……建议你在家庭练习时，可以尝试放慢书写速度，专注于笔画的细节。

### 体育 sports · 远远 · L2（标签：进步明显 / 需纠动作）— ⚠️ 含占位符泄漏
> 远远，今天体育课你**[立定跳远]**的动作进步明显，但**[摆臂和蹬地]**的配合还需要加强。……不过，**[摆臂和蹬地]**的配合还有待提高……

### 美术 art · 满满 · L2（标签：起稿准确 / 细节丰富）— ⚠️ 含占位符泄漏
> 满满，今天美术课你**[在绘制单个石膏球时]**完成度很高，**[明暗交界线下得非常准确]**。

## 五、家长视角分析

家长是课评的最终读者。模拟中我们以「家长打开课评」的心态逐份阅读，结论如下：

### 5.1 家长能看懂、愿意看（多数学科）
- **编程 / 舞蹈 / 书法 / 英语 / 学科辅导**：课评读起来像老师亲笔写的，有具体项目名（for 循环、永字八法、购物对话）、有孩子名字昵称、有褒有贬、有可执行的家庭建议。**家长能确切知道孩子这周学了什么、卡在哪、回家练什么**。
- 尤其是**进步曲线**被自然呈现：舞蹈从「略显害羞」到「完全放开」，英语从「积极开口」到「不敢大声说」再到「角色扮演很投入」——家长能看到孩子的成长波动，而非千篇一律的表扬。

### 5.2 家长会困惑、甚至怀疑系统（体育 / 美术）
- 体育课评里出现大量 **「[立定跳远]的动作」「你[折返跑]表现非常出色」「[从本节课课件/教案中抽取的具体项目/动作名称][具体完成情况]」** 这类带方括号的怪异文字。家长完全看不懂这些方括号是什么意思，第一反应会是：**「这课评没写完 / 系统出 bug 了」**，对机构专业度产生怀疑。
- 美术 L2 同样出现「[在绘制单个石膏球时]」——虽然是褒义内容，但方括号让整段显得半成品。
- 这直接拉低了家长信任。体育作为 7 个学科里泄漏最严重的一个（5 课全中），是家长体验的「重灾区」。

### 5.3 家长视角的整体反馈
| 维度 | 家长感受 |
|------|----------|
| 信息量 | 高——知道学了啥、表现如何、回家练啥 |
| 真实感 | 高（coding/dance/calligraphy/english/tutoring）；低（sports/art 因占位符） |
| 对孩子了解 | 好——标签与内容呼应，能看到具体优点和待改进点 |
| 情绪 | 被鼓励（建议具体、语气正向）；但体育/美术的方括号会让家长皱眉 |
| 信任度 | 6/7 学科高；体育因系统性占位符泄漏明显受损 |

## 六、用户（教师）视角分析

教师是系统的直接操作者。模拟真实操作后的体验：

### 6.1 操作流程顺畅、闭环完整 ✅
建班 → 加学生 → 粘贴课程内容建课次 → 选标签 + 写评语 → 一键生成，链路全程无卡点。标签现能正确传入并体现在课评中（上轮 bug 已修复，本轮 34 份均验证通过）。

### 6.2 标签与评语作为「事实锚点」效果好 ✅
教师点选的标签几乎都被 AI 如实呼应：
- 编程 L4「概念混淆/需多次提醒」→ 课评写「容易写成死循环，需要老师在旁边反复提醒」；
- 书法 L3「易急躁」→ 「速度有些快，显得有些急躁」；
- 学科辅导 L2「存在漏洞/需巩固」→ 「小数点位数常错」。
这正是设计预期：教师用标签定调，AI 不虚构、不矛盾。

### 6.3 教师视角的痛点（真实体验，非主观挑刺）

**痛点 A：体育/美术生成质量不稳定（方括号占位符）**
教师粘贴了正常课程内容，但生成结果里夹着 `[...]`。教师必须手动删掉这些括号才能发給家长——这本质是系统 prompt 缺陷（见第七节），但教师体感是「同一个功能，体育总出怪字，书法却好好的」，会认为生成质量看运气。

**痛点 B：偶发超时、生成中断**
美术 L3 直接 120s 超时失败，前端会弹失败。教师需重试，打断工作流。弱模型下 35 次里有 1 次，频率不高但确实存在。

**痛点 C：字数偶发逼近/略超上限**
编程 L5（316 字）、英语 L3（317 字）已贴近 320 上限，scorer 判 `length_ok:False`。教师若追求评分全绿，会困惑「为什么字数标红」。建议后端硬截断更果断，或放宽临界宽容度。

**痛点 D：缺少「一键批量生成全班」的显性反馈**
当前详情页按学生逐一点「AI 生成课评」。模拟中每次只测 1 名学生，未压测多学生并发；但教师视角下，若全班 20 人需逐个点，操作成本偏高（属产品层，非本轮重点）。

### 6.4 教师视角的整体评价
| 维度 | 评价 |
|------|------|
| 上手成本 | 低——流程直观，无需培训 |
| 内容质量（coding/dance/calligraphy/english/tutoring） | 高——可用、可信、能发家长 |
| 内容质量（sports/art） | 中偏低——需人工修括号 |
| 标签/评语生效 | 好——本轮稳定验证 |
| 稳定性 | 中——偶发超时 + 占位符泄漏 |
| 效率 | 中——单学生逐份生成，缺批量 |

## 七、关键问题发现（供后续修复参考，本轮未修改）

### 问题 1（严重）：方括号占位符被弱模型原样抄入输出
- **位置**：`src/ai/prompt_builder.py` 第 116–123 行 `SUBJECT_OPENING` 字典，每个学科开头范式都含 `[从本节课课件/教案中抽取的具体项目/动作名称]`、`[具体完成情况]` 等**方括号占位符**，本意是「指令：请替换为真实内容」。
- **现象**：GLM-4-Flash 把 `[ ]` 当成字面文本，要么整段照抄（如体育 L3「[从本节课课件/教案中抽取的具体项目/动作名称][具体完成情况]」），要么把真实内容塞进括号里（如「你[立定跳远]的动作」）。
- **影响学科**：体育（5/5 全泄漏）、美术（部分）。coding/dance/calligraphy/english/tutoring 偶发但本轮未泄漏。
- **根因**：用「带方括号的占位符」做少样本指令，弱模型无法区分「占位符」与「待填内容」。
- **方向**（非本轮执行）：把开头范式改为自然语言指令（如「请用本节课真实项目名开头，例如『你独立完成了 XX 小项目』」），或后端用正则把 `[...]` 占位符在 finalize 阶段强制剥离。

### 问题 2（中）：弱模型偶发超时
- 美术 L3 因 `open.bigmodel.cn` 120s 读取超时失败。建议增加失败重试（1 次）+ 前端明确「生成失败，点此重试」而非静默/未知错误。

### 问题 3（轻）：字数临界标红
- 部分课评 316–317 字贴近 320 上限，scorer 判不通过。建议 finalize 阶段对临界值做更果断的硬截断，或评分对 ±5% 宽容。

### 问题 4（轻）：art L2 选了「起稿准确」标签，课评却写「在细节刻画上还可以再细致一些」——正负面略有错位，但属弱模型语义误差，不影响主结论。

## 八、使用体验总结

**一句话结论**：系统对 7 个学科、连续 5 课的模拟中，**34/35 份课评达到「可直接发给家长」的质量**，标签与教师评语作为事实锚点的机制运转良好；但**体育、美术两个学科因 prompt 里的方括号占位符被弱模型原样抄出，生成结果带「[...]」半成品文字，严重拉低家长信任与教师效率**，是本次模拟暴露的最关键、最该优先修复的体验问题。

### 双视角速览
- **家长视角**：6/7 学科看到的是「具体、真实、有温度」的课评，能了解孩子学了什么、卡在哪、回家练什么；体育/美术因占位符让家长误以为「课评没写完 / 系统有 bug」。
- **用户（教师）视角**：操作流程顺畅、标签生效稳定、内容可用性高；主要痛点是体育/美术的占位符需手工修、偶发超时打断、字数临界标红。

### 优先修复建议（按影响排序）
1. **P0**：剥离 `SUBJECT_OPENING` 中的方括号占位符（改自然语言指令 or finalize 阶段正则清除），先救体育/美术。
2. **P1**：生成失败增加自动重试 + 明确重试提示，消除超时导致的流程中断。
3. **P2**：finalize 阶段对字数做更果断硬截断，避免临界标红。
